# OR-Agent — 路径图和验证检查点

该路径图追溯了里程碑和验证检查点。[README](../README.zh-CN.md) 介绍了产品及其使用方式；[技术文档](memory.zh-CN.md) 解释了实现选择。

<a id="m0--cadrage-gap"></a>
## M0 — 间隙定义

目标：确定能力分配合同。

- [x] 确定每项任务的强制性、不可分割和唯一分配。
- [x] 定义任务-资源配对的成本和消耗，能力以及总成本的最小化。
- [x] 设定整数边界和明确单位，包含负成本和零消耗。
- [x] 将间隙与路由、优先级和调度进行界定。
- [x] 区分模型验证、源数据一致性、可行性与最优性。

验证：合同在 [models.py](../or_agent/models.py) 中实现，并通过模式和求解测试覆盖。**状态：已完成。**

<a id="m1--validation-et-représentation"></a>
## M1 — 验证与表示

目标：以严格且可控的模型表示数据。

- [x] 实现封闭模型 `Gap`、`Extraction` 和 `Candidate`。
- [x] 控制标识符、唯一性、维度、数值域和单位。
- [x] 在矩阵中将资源设置为行、任务设置为列。
- [x] 要求每个提取 `ready` 的字段具有精确来源。
- [x] 拒绝模糊的 JSON、不完整数据和未知字段。

验证：有效和拒绝案例由 [test_models.py](../tests/test_models.py) 覆盖。**状态：结构验证已完成。**

<a id="m2--résolution-cp-sat"></a>
## M2 — CP-SAT 求解

目标：在时间限制内将提供的间隙转换并求解。

- [x] 构建二元变量、唯一分配、能力以及整数目标。
- [x] 保留候选方案、目标、边界、版本、参数和求解器时间。
- [x] 区分已证明最优解、可行候选、不可行、未决结果和技术错误。
- [x] 将小规模问题与穷举法进行比较，并测试数值和时间限制。

验证：转换、状态和参考的完整性由 [test_solver.py](../tests/test_solver.py) 覆盖。**状态：针对提供的间隙已完成。**

<a id="m3--vérification-indépendante"></a>
## M3 — 独立验证

目标：通过独立求解器计算来控制分配。

- [x] 控制标识符、任务的精确覆盖和重复项。
- [x] 重新计算整数负载并验证能力。
- [x] 重新计算成本并将其与声明目标进行比较。
- [x] 返回结构化的违规信息并拒绝格式错误的候选方案。
- [x] 测试遗漏、重复项、未知资源、超限和损坏成本。

验证：注入的损坏情况由 [test_verify.py](../tests/test_verify.py) 覆盖。**状态：可行性与成本验证已完成。**

<a id="m4--boucle-agent"></a>
## M4 — Agent 循环

目标：将 Ollama、验证与解决纳入一个有限循环中。

- [x] 交付生成 CLI 及结构化诊断。
- [x] 实现并比较基于提示的 JSON、基于模式的生成以及有界校正。
- [x] 限制生成调用次数为一次，或最多两次并配合校正，同时应用预算限制。
- [x] 保留已解析数据在校正过程中的状态。
- [x] 记录原始响应、错误、观察结果和资源检查。
- [x] 使用受控响应测试分支，并在 CLI 中实际运行一个 Ollama 试点。

验证：由 [test_agent.py](../tests/test_agent.py) 覆盖。**状态：已完成，无需人工介入的 CLI 循环。**

<a id="m5--évaluation"></a>
## M5 — 评估

目标：基于独立参考材料评估表述和最终响应。

- [x] 准备初始数据集共 16 个案例：7 个开发案例和 9 个测试案例。
- [x] 准备扩展数据集共 130 个案例：30 个开发案例和 100 个测试案例。
- [x] 审核参考材料、指纹及开发与测试集之间的分类划分。
- [x] 实现日志化活动和指标，并在分母中计入缺失结果。
- [x] 完成初始、扩展及独立的历史评估。
- [x] 分析遗漏、错误关联、位置错位和校正情况。

验证：由 [test_benchmark_data.py](../tests/test_benchmark_data.py) 和 [test_extended_corpus.py](../tests/test_extended_corpus.py) 覆盖，评估协议和指标由评估测试定义。**状态：探索性评估已完成。** 用于决策的有用结果已汇总在 [记忆](memory.zh-CN.md#m5--évaluation) 中。

<a id="extensions--routage-déterministe-et-hitl"></a>
## 扩展 — 确定性路由与人工介入（HITL）

目标：直接处理认证格式，并将其他表述提交给明确的人工审查。

- [x] 提取包含关联、单位、引用及源位置的事实信息。
- [x] 确认覆盖完整性、标准约束、无矛盾性以及规范性重建。
- [x] 构建并解决无需大语言模型（LLM）参与的 `VERIFIED_COMPLETE` 输入。
- [x] 否则生成人工草稿或可选的 Ollama 提案，包含未知项和诊断说明。
- [x] 增加校正、验证、审查、范围确认、批准与拒绝环节。
- [x] 将权限与原始源及精确提案关联，并在修改后立即失效。
- [x] 在草稿重写后，保留原始源的阻塞项。
- [x] 通过模拟审批验证守卫机制。

验证：修订、权限与路由由 [test_hitl.py](../tests/test_hitl.py) 和 [test_routing.py](../tests/test_routing.py) 覆盖。**状态：在技术范围 V1 上已完成。**
